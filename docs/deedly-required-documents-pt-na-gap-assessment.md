## 4. Acceptance tests needed

**Conditions (per approved key, starting with the 12-fact demo subset):**
- `yes` / `no` / `unknown` evaluation per key; `unknown` → rule in
  `unevaluatedRules`, fact in `unevaluatedFacts`, never silently `no`.
- An existing requirement is **not** withdrawn when its fact becomes
  unknown; it is withdrawn only on a definite `no` after evaluation.
- Unknown/unregistered `condition_key` in a rule → flagged, never applied.
- `seller_bond_registered` never derivable from purchaser finance data;
  `buyer_bond_finance` never derivable from title/bond-cancellation data.

**Scoped facts:**
- Multi-party matter: `party_is_entity`/`party_is_trust`/
  `marriage_affects_capacity` evaluated per relevant party; a party lacking
  the fact keeps dependent rules unevaluated.

  matter in the aggregate.
- Whichever aggregation rule is approved ("any relevant entity" vs
  per-entity instances) is asserted explicitly, including mixed answers.

**Stage handling:**
- A conditional/baseline rule surfaces at its due stage; stage-gated
  blocking fires only when the rule applies (conditional `no` does not
  block).
- Validity-window rules (DOC-045, DOC-054) flag refresh rather than pass
  permanently.

- Unconfigured/unsupported classification → "Requirements not configured",
